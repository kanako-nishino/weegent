# 公開前チェックリスト

作成: 2026-09-27 / 関連: [cf7-setup.md](cf7-setup.md)

---

## 1. テーマ(コード)側で公開前に片付けるもの

- [x] `functions.php` の `custom_wp_pagenavi()` 内に残っているデバッグ用の `error_log($html);` を削除する
- [ ] `npm run build` を実行し、`css/style.css` が最新のSassから書き出されていることを確認する
- [x] 残っている仮リンク(`href="#"`)を解消する
  - [x] フッターのSNSアイコン(YouTube / note / X)
  - [x] 動画セクションの動画カード・「YouTubeチャンネルを見る」(動画カスタム投稿)
- [x] 404ページを作成する(`404.php`。デザインカンプがないため下層ページの見出しエリアとボタンを流用)
- [ ] テーマのスクリーンショット(`screenshot.png`)を用意する(任意。管理画面の外観一覧に表示される)

## 2. サーバーへ上げるファイル

- [ ] テーマフォルダ内の、本番に不要なものを除外してアップロードする
  - `node_modules/`(約58MB)
  - `weegent-wp`(テーマフォルダ自身を指すシンボリックリンク。移行ツールで無限ループや容量の肥大化の原因になる)
  - `.git/`、`docs/`、`package.json`、`package-lock.json`
  - `sass/`、`*.map`(任意。残しても表示に影響はない)
- [ ] ローカルのテーマはシンボリックリンク(Local Sites → Desktop)で配置しているため、All-in-One WP Migration でエクスポートしたデータにテーマが正しく含まれているか確認する(含まれない場合は、テーマをzipにして別途アップロードする)

## 3. サーバー・WordPress本体

- [ ] ローカル(Local)と本番サーバーのPHPバージョンをそろえてから書き出す(test.weegent.jp は PHP 8.1。XserverのPHPバージョンはドメイン単位の設定なので、変更すると本番にも影響する)
- [ ] SSL(https)が有効で、http → https にリダイレクトされる
- [ ] 「設定 > 一般」のサイトアドレスが本番URL(https)になっている
- [ ] 移行後に、画像やリンクがローカルのURL(`weegent.local`)のまま残っていない
- [ ] 「設定 > パーマリンク設定」を開いて「変更を保存」を押す(移行後の404対策)
- [ ] `wp-config.php` の `WP_DEBUG` が `false`、`WP_ENVIRONMENT_TYPE` が `production`(または未設定)
- [ ] WordPress本体・プラグインを最新版にする
- [ ] 使っていないプラグインを停止・削除する
- [ ] クライアントのユーザー(本番と同じID・パスワード)をローカルにも作っておく(ローカルのデータを丸ごとインポートすると、既存サイトのユーザーはローカルのものに置き換わるため)
- [ ] ローカルの管理者ユーザー名 `wp-admin` を、推測されにくいものに変更する
- [ ] CF7のメール件名に付けた「【テスト環境】」などを外し、送信先を本番の宛先にする
- [ ] 管理者ユーザーのパスワードが十分に強い(ユーザー名に `admin` を使わない)
- [ ] ログイン画面(`wp-login.php`)の保護を確認する(既存サイトはサーバー側の設定で「Input your ID and Password.」の認証がかかっている。リニューアル後も同じ保護が残っているか確認する)
- [ ] `.htaccess` に残っている旧サイトのSiteGuardの設定(`SITEGUARD_PLUGIN_SETTINGS`、ログインURL `login_93495`)を整理する(新サイトではSiteGuardを使っていない)
- [ ] バックアップの取得方法を決めておく(サーバーの自動バックアップ、またはプラグイン)

## 4. 管理画面の設定・コンテンツ

### 固定ページ
- [ ] 必要な固定ページがすべて公開されていて、スラッグが正しい
  - トップ用ページ / `company` / `privacy-policy` / `news`
  - `inbound` / `outbound-enterprise` / `outbound-smb` / `test-marketing`
  - `contact` / `document-download` / `case-download` / `resource-download`
  - 上のフォーム4ページそれぞれの子ページ `thanks`
- [ ] 「設定 > 表示設定」で、ホームページにトップ用ページ、投稿ページに「お知らせ」が選ばれている

### 投稿データ
- [ ] ダミーの投稿(お知らせ・導入事例・お役立ち資料)を削除する、または差し替える
- [ ] お役立ち資料: 各資料にカテゴリ・説明文・訴求ポイント・アイキャッチが入っている
- [ ] 導入事例: 業種・従業員数・課題・企業名・ロゴ、投稿者(担当者)のプロフィールが入っている
- [ ] 導入事例・お役立ち資料: 各メニューの「ページごとの表示設定」で各ページに表示するものを選ぶ(未選択なら新着3件が自動で表示される)
- [ ] 動画: タイトル・YouTubeのURL・チャンネル名を登録し、サムネイルが表示されることを確認する
- [ ] 動画: 「動画 > ページごとの表示設定」で各ページの動画を選ぶ(未選択なら新着3件が自動で表示される)

## 5. フォーム(Contact Form 7)

- [ ] 4フォームのタイトルが `cf7-setup.md` の通りになっている(タイトルが違うとフォームが表示されない)
- [ ] 通知メールの送信先が、本番で受け取る担当者のアドレスになっている
- [ ] 送信元(From)が本番ドメインのアドレス(例: `noreply@weegent.jp`)になっている
- [ ] 自動返信(メール(2))の `Reply-To` と「送信専用アドレス」の注意書きが、実際の運用と合っている
- [ ] 自動返信の署名(社名・住所・電話番号)が正しい
- [ ] reCAPTCHA v3
  - [ ] クライアント(または会社)のGoogleアカウントでキーを発行している
  - [ ] 本番ドメインを登録し、本番用のキーをCF7に登録している
  - [ ] フォームページにだけバッジが表示される(トップなどには出ない)
- [ ] メールが届くようにする: WP Mail SMTP などでSMTPを設定する(推奨)
- [ ] Flamingo を導入し、送信内容が管理画面に保存されることを確認する(推奨)

### 本番での送信テスト(実際のメールアドレスで)
- [ ] お問い合わせ(`/contact/`)
- [ ] 資料3点セット(`/document-download/`)
- [ ] 事例集(`/case-download/`)
- [ ] お役立ち資料 … 個別の資料カードから(通知メールに資料名が入る)
- [ ] お役立ち資料 … 「すべての資料をダウンロード」から(「すべてのお役立ち資料（一括請求）」になる)
- [ ] DL系thanksページ内の相談フォーム(送信元ページがthanksページのURLになる)
- [ ] 各フォームで、通知・自動返信の2通が**受信箱に**届く(迷惑メールフォルダに入っていない。Gmail・Outlookなど複数で確認)
- [ ] 送信後、それぞれのthanksページに移動する
- [ ] 必須項目が空のときやメールアドレスの形式が違うときに、エラーメッセージが表示される
- [ ] `/document/記事名/` を開くと、その資料のDLフォームへ転送される

## 6. SEO・計測

- [ ] 「設定 > 表示設定」の「検索エンジンがサイトをインデックスしないようにする」の**チェックを外す**(本番のみ)
- [ ] SEO SIMPLE PACK: サイトのタイトル・ディスクリプション・OGP画像を設定する
- [ ] フォームページ・thanksページを noindex にする(SEO SIMPLE PACK の各ページ設定)
- [ ] サイトアイコン(ファビコン)を設定する(「外観 > カスタマイズ > サイト基本情報」)
- [ ] Google Search Console にサイトを登録し、サイトマップ(`/wp-sitemap.xml`)を送信する
- [ ] Google アナリティクス(GA4)/ タグマネージャーを設置する
- [ ] 各thanksページの表示をコンバージョンとして設定する(広告を使う場合は広告側のタグも)
